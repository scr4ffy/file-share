# Передача файлов напрямую между устройствами

Сайт из статических файлов. Файлы идут напрямую между браузерами (WebRTC), на сервере не хранятся, размера ограничения нет (проверено на 4,5 ГБ, ограничение только диск получателя).

Файлы проекта (все должны лежать в одной папке):

- `index.html` — сам сайт
- `sw.js` — воркер для потокового сохранения больших файлов
- `mqtt.min.js` — клиент для связи с публичными MQTT-серверами (mqtt.js 5.16)
- `qrcode.js` — генератор QR-кода
- `jsQR.js` — чтение QR-кода с камеры

## Как выложить бесплатно

Нужен хостинг с HTTPS (без него WebRTC и потоковое сохранение не работают). Любой из вариантов:

1. **GitHub Pages.** Создайте репозиторий, загрузите все файлы в корень, в Settings → Pages выберите ветку `main` и папку `/ (root)`. Адрес будет `https://ваш-логин.github.io/имя-репозитория/`.
2. **Cloudflare Pages.** Workers & Pages → Create → Pages → Upload assets, перетащите папку.
3. **Netlify Drop.** Откройте app.netlify.com/drop и перетащите папку.

## Как пользоваться

1. Откройте сайт: вы увидите свой код и ссылку (код запоминается в браузере, ссылка постоянная).
2. Отправьте ссылку другу любым способом (или покажите QR-код).
3. Друг открывает ссылку, устройства соединяются, и любой из вас может перетащить файлы в окно.
4. Получатель нажимает «Принять» и выбирает, куда сохранить.

Обе вкладки должны быть открыты, пока идёт передача.

## Как устройства находят друг друга

Сайт подключается сразу к нескольким публичным серверам обмена сообщениями (MQTT-брокеры EMQX, HiveMQ, Mosquitto и сервис ntfy.sh) и отправляет служебные сообщения во все. Достаточно, чтобы работал хотя бы один. Служебные сообщения зашифрованы кодом друга (AES-GCM), а сами файлы через эти серверы не идут: они передаются напрямую между браузерами. Список серверов лежит в массиве `RELAYS` в начале скрипта `index.html`.

Если вообще ни один сервер недоступен, вверху появится сообщение, и раскроется блок «Подключение без сервера»:

1. Один человек нажимает «Создать приглашение» и отправляет другу полученную ссылку (мессенджером, письмом, любым способом) или показывает на экране QR-код.
2. Друг открывает ссылку или нажимает «Сканировать QR-код» и наводит камеру. Страница сама создаст ответ, его нужно отправить обратно (ссылкой или тоже QR-кодом).
3. Первый вставляет ответ в поле «Шаг 2» (или сканирует QR друга). Устройства соединяются, и дальше всё работает как обычно, в обе стороны.

Коды короткие (около 100-200 символов, влезают в QR). Если короткий код у друга не сработал, есть галочка «Длинный код». Если оба устройства в разных сетях, для этого режима нужен доступ к STUN-серверу (Google, Cloudflare). Если он недоступен, сайт предупредит об этом, и соединение получится только внутри одной сети.

## Продолжение после обрыва

Если связь оборвалась посреди передачи, обе стороны показывают «Соединение прервано», сайт сам пытается переподключиться (сначала через 3 секунды, потом реже, до 15 минут) и продолжает файл с того места, где остановились, а не сначала. Работает, пока обе вкладки остаются открытыми. Если вкладку закрыли или обновили, передачу придётся начать заново.

## Ограничения

- **Оба участника должны быть онлайн одновременно.** Файл не «лежит» на сервере.
- **Соединение может не установиться** у части пар устройств (мобильный интернет, строгие роутеры, корпоративные сети). Тогда нужен TURN-сервер, который пересылает трафик. Впишите его в массив `ICE_SERVERS` в начале скрипта в `index.html`:

  ```js
  { urls: 'turn:turn.example.com:3478', username: 'user', credential: 'pass' }
  ```

  Через TURN идёт весь трафик, поэтому у бесплатных TURN обычно есть лимит по объёму. Свой TURN можно поднять на VPS (coturn).
- **Сохранение больших файлов.** В Chrome, Edge и Opera на компьютере файл пишется прямо на диск. В остальных браузерах используется потоковая загрузка через Service Worker. Если и она недоступна (например, приватный режим Firefox), файл собирается в памяти, и для файлов больше 1-2 ГБ нужен Chrome или Edge.
- **Свои серверы.** Можно указать свои MQTT-брокеры и ntfy, открыв сайт с параметрами `?mqtt=wss://адрес:порт/путь&ntfy=https://адрес`.
